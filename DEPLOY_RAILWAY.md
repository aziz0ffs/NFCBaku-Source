# Railway deployment status

The PHP/Apache Docker image and Volume-aware startup are provided in `Dockerfile` and `deploy/railway/`. The Railway project is named `nfc-baku-staging` (despite its public domain), with service `nfc-baku`, private GitHub source `aziz0ffs/NFCBaku-LinkStack`, persistent Volume mounted at `/data`, and public URL https://nfc-baku-production.up.railway.app/. Its code is also published as corresponding source at https://github.com/aziz0ffs/NFCBaku-Source. Public HTTPS home, login, profile, and selected static assets returned 200; sensitive paths returned 403. The login page offered an HTTPS form and Secure session cookie. The SQLite database passed integrity checks with the migrated users, and the upload/session directories were writable by the web server. Authenticated login, actual upload, scheduled backups and restoration have NOT been tested.

- Keep `.env`, `database/database.sqlite`, user-uploaded files under `assets/img/`, runtime `storage/` contents, and backups out of Git. Upload the existing `.env` and `database.sqlite` to the persistent Railway Volume at `/data/.env` and `/data/database/database.sqlite`. Preserve the original `APP_KEY`. The app's environment editor reads `.env` from the Volume; it is deliberately not baked into the image or imported wholesale into Railway Variables.
- Upload the current `assets/img/` to `/data/assets/img/` and `assets/linkstack/images/` to `/data/assets/linkstack/images/`, preserving the site avatar/favicon. The startup script links these paths and the runtime `storage/` to subdirectories of the same Volume; defaults are copied only if missing. Never mount an empty Volume on `/app`.
- Attach one Volume to the service at `/data`. Railway mounts it at runtime, not at build time. The startup script refuses to create a blank SQLite database and only starts after the real database and `.env` are present.
- Ensure `APP_ENV=production`, `APP_DEBUG=false`, `DB_CONNECTION=sqlite` in the uploaded `.env`. Keep the Volume and its backup access private. Railway Variables include `PORT=8080`, `FORCE_HTTPS=true` and `SESSION_SECURE_COOKIE=true`; verify generated links, cookies, redirects, login, uploaded images, and sensitive-file denial after each deployment.
- The local `start-local.sh`/`php -S` is not used for Railway. Enable regular Volume backups, and test restoration of database and images together. Do not regenerate `APP_KEY` when restoring existing data.
- Upstream LinkStack is distributed under AGPL-3.0 (see `LICENSE`). The modified corresponding source and `MODIFICATIONS.md` are publicly offered from the app at https://github.com/aziz0ffs/NFCBaku-Source. Sync the public tree with each private source revision before deploying it.

Railway documentation: https://docs.railway.com/volumes and https://docs.railway.com/guides/laravel
